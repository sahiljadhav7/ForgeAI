# Spec: New frontend (Daybreak landing page)

Status: ready-for-agent
Branch: `feat/new-frontend`

## Problem

The landing page (`app/(main)/page.tsx`) is a generic dark page: gray/blue gradient serif headings, a star-field background, a "Powered by Gemini" badge and a plain composer. The product is also being renamed from **ForgeAI** to **Daybreak**. We want a landing page that follows the full-viewport video hero in `design.md`, with the sections below it restyled to match. The whole app moves to Inter and dark mode, and the brand name changes everywhere users see it.

## Source of truth

`design.md` (repo root) is the **pixel reference** for the hero: coordinates, the `--u` unit, colors, radii, shadows, letter-spacing, the three responsive architectures and the entrance animation. It was written as a prompt for a standalone HTML mockup. **Where it conflicts with this spec, this spec wins.** The overrides are listed below.

### Overrides to `design.md`

| `design.md` says | This spec says |
| --- | --- |
| One self-contained HTML file | A Next.js page in `app/(landing)/page.tsx`. Hero CSS is ported near-literally into a CSS module `app/(landing)/landing.module.css`. Tailwind is used everywhere else. |
| Brand "Fastshot", concentric-circle mark | Brand **Daybreak**, with a **rising-sun mark**: a half-sun on a horizon line, peach→lavender gradient, same 34×34u box and position. |
| Title/meta "Fastshot — …" | `<title>Daybreak — Describe an app. We'll build it.</title>`, description "Daybreak turns a written description into a working React app." |
| Background video from a third-party CloudFront URL | `public/daybreak-hero.mp4` (renamed from `public/ForgeAI-video.mp4`), plus a first-frame poster image. |
| `.stage` fixed, `body overflow:hidden`, "no second section below the fold" | The hero is a `100dvh` section. The video scrolls away with it and the page scrolls to the restyled sections below. |
| Placeholder is a `<p>`, form never submits | A real `<textarea>` in the placeholder's position and typography. It submits for real (see Composer). |
| Three chips: Attach Screens / Attach a Figma / Today's Theme | Three **suggestion chips** in the spec's chip styling, chosen at random per page load. |
| "Sonnet 4.5" model label + chevron | Removed. |
| Paperclip attach | Removed. The send circle keeps its exact spec coordinates. Nothing shifts into the gap. |
| Footer "Built by engineers from" + Google/Cisco/Adobe logos | Replaced by a "See how it works" scroll cue in the same position and typography (14.01u, weight 480). Clicking it scrolls to How it works. |
| Nav: Features · Examples · Pricing · Docs → `#` | Features, Examples and Pricing are smooth-scroll anchors to `#features`, `#examples` and `#pricing`. Docs is removed. |
| Get Started is presentational | Signed out: opens Clerk sign-up. Signed in: replaced by a **My projects** button (same styling, links to `/projects`) plus the Clerk `UserButton`. The burger sheet mirrors this. |
| Card fixed at 143u tall | The card grows downward as the textarea grows, capped at about 2× the base height, then the textarea scrolls. The toolbar stays pinned to the card's bottom edge. Empty state is pixel-exact. |

Everything in `design.md` not listed here is kept as written: nav geometry, headline typography, the glass card, chip styling, send styling, focus ring, the burger menu mechanics, the tablet and compact media queries (adjusted to the removed controls), and the entrance timings (minus the removed elements).

## Decisions

### Scope
- The **landing page** is redesigned on this branch.
- `/workspace`, `/projects` and the auth pages get only the app-wide **font** and **forced dark** changes, and the **rename**. Their layouts are not redesigned.

### Routing and layout
- Move the landing page to `app/(landing)/page.tsx` with its own `layout.tsx` (no top margin, no global header).
- Move `<Header />` out of `app/layout.tsx` into `app/(main)/layout.tsx` and `app/(auth)/layout.tsx`, so those pages look unchanged.
- URLs don't change.

### Fonts and theme (app-wide)
- Load **Inter** (variable, `opsz` axis) with `next/font/google` in the root layout. Remove **Lora** and **DM Sans**.
- `font-sans` and `font-serif` both resolve to Inter. The current `font-serif` headings (`components/reusable.tsx`, `components/PricingModal.tsx`, `app/(main)/workspace/error.tsx`) become Inter display: `font-variation-settings: "opsz" 32`, weight 410.
- `ThemeProvider` gets `forcedTheme="dark"`. Nothing in the app toggles the theme today.

### Rename to Daybreak (in-app text)
- Landing page and root-layout metadata. The root layout's `"Ai App Builder"` / `"Generated by create next app"` becomes Daybreak defaults.
- `components/ChatPanel.tsx` image alt text ("Forge" → "Daybreak").
- `components/CodePanel.tsx` ZIP export: package name `daybreak-app`, title "Daybreak App", filename `daybreak-app.zip`. The bundled README must **not** link to `https://forge.app`, which isn't our domain. It says "Generated with Daybreak." with no link.
- `lib/constants.ts` plan feature: "Access to Daybreak Pro Agent".
- `README.md` is rewritten to say Daybreak. The live-demo URL stays forgeai.lol until the domain moves.
- Out of scope, left to the owner: the domain, renaming the GitHub repo, the Clerk app name and email templates, the Vercel project, and `scripts/capture-readme-visuals.mjs`'s URL.

### Hero
- Nav, headline ("Describe an app. We'll build it."), composer, scroll cue and entrance animation per `design.md` plus the overrides above.
- No subtitle and no "Powered by Gemini" badge.
- Video: `autoPlay muted loop playsInline`, `object-fit: cover`, a `poster` (first frame, committed as `public/daybreak-hero-poster.jpg` or `.webp`).
  - `preload="auto"` only when the viewport is desktop-sized (≥1181px); `preload="metadata"` otherwise.
  - Under `prefers-reduced-motion: reduce`, don't autoplay; show the poster only.
- A short gradient at the bottom of the hero fades the video into the page base color (`#14111c`).
- The entrance animation runs once on first paint under `prefers-reduced-motion: no-preference`. Implement the spec's `anim` class and teardown in React (a class on the landing root that's removed after the last animation or 2600ms), not a `<head>` script.

### Composer
- A `<textarea>` in the `.ph` position and typography (`#8B8C8E`, 9.97u, one line, ellipsis when empty).
- The placeholder rotates through the existing `PLACEHOLDERS` every 3s, pausing while focused or non-empty (current behavior).
- Enter submits; Shift+Enter adds a new line. Send is disabled when the prompt is empty or whitespace only.
- **Signed in:** `router.push("/workspace?prompt=" + encodeURIComponent(prompt.trim()))`.
- **Signed out:** open the Clerk sign-in modal with a redirect to that same `/workspace?prompt=…` URL (`forceRedirectUrl`/`signUpForceRedirectUrl`), so the typed prompt survives sign-in. It must never return silently, as today's `handleSubmit` does.
- **Suggestion chips:** `SUGGESTIONS` in `lib/data.ts` becomes `{ label, prompt }[]`, with short labels such as "Spotify stats" and "Kanban board".
  - Three are picked at random **after mount**. Server and first client render show the first three to avoid a hydration mismatch, then swap.
  - Clicking a chip sets the textarea to its `prompt` and focuses it.
  - Chips are auto-width in the spec's chip styling (height, radius, gradient, border, font, icon, label offset). Each keeps one of the spec's filled-blob icons.
- The right cluster is just the send circle at the spec's absolute coordinates. Tablet and phone follow the spec's flex rules without the model label and paperclip, with send still right-aligned.

### Below the hero: same structure, restyled
The existing sections are kept in their current order and content: demo video (**Examples**, `id="examples"`), How it works (`id="how-it-works"`), Everything you need (**Features**, `id="features"`), Simple pricing (`id="pricing"`), the Start building CTA and the footer. Changes:

- **Palette tokens** ("dawn dusk"), defined once as CSS variables so later redesigns can reuse them:
  - `--db-base: #14111c` (page background below the hero)
  - `--db-surface`: composer glass tinted slightly warm (from `rgba(41,41,43,.955)`), with the inset border `rgba(214,228,255,.14)`
  - `--db-accent`: the send gradient `linear-gradient(163deg, #FBBC94 0%, #F49D70 46%, #E88654 100%)`, with solid fallback `#F49D70`
  - `--db-lavender: #9C86CE`
  - `--db-text: warm white`, `--db-muted: #98999C`
  - Faint radial dawn glows (peach low, lavender high) behind Pricing and the CTA.
- The `GrayTitle`/`BlueTitle` gradient headings become plain warm-white Inter display. Section labels ("How it works") are lavender.
- Cards use `--db-surface` with a radius of about 26px. Buttons and highlights (step numbers, "Pro") use `--db-accent`. No blue anywhere on the landing page.
- **Pricing:** Clerk `<PricingTable>` themed via `appearance`: Inter, `--db-surface` cards, `--db-accent` primary button, `--db-muted` text.
- **Scroll reveal:** each section fades and rises 4–8px once when it enters the viewport, using one shared `IntersectionObserver` and the hero's `--e-soft` easing. Disabled under reduced motion.
- `GravityStarsBackground` is removed from the landing page.

### Housekeeping
- Delete `public/ForgeAI-video.mp4:Zone.Identifier` (a Windows download marker).
- Rename `public/ForgeAI-video.mp4` → `public/daybreak-hero.mp4`.

## Out of scope
- Redesigning `/workspace`, `/projects` and the auth pages, beyond font, theme and rename.
- Image attach from the homepage; Figma import.
- Replacing Clerk (auth or billing), moving the database, replacing Supabase Storage.
- Showing credits on the landing nav. The global `Header` keeps showing them on other pages.
- A new `/logo.png` for the global `Header` (it's an image asset, not text). This is a follow-up once a Daybreak logo exists.

## Testing
- Vitest runs in the `node` environment on `**/*.test.ts`. Pure logic gets unit tests:
  - building the `/workspace?prompt=…` URL (trimming, encoding, rejecting empty or whitespace-only prompts),
  - picking three random suggestions (with an injectable RNG: distinct picks, always three, stable fallback).
- Visual checks are done by running the app and comparing screenshots with `design.md`:
  - desktop at 1560×1008 against the spec's coordinates (send circle at card-relative x=659, y=94, 35u, overhanging the chip row by 7u),
  - tablet around 900×900: one-row toolbar,
  - phone around 390×844: burger menu, two-row toolbar, send on the right,
  - one short-landscape viewport (under 560px tall).
- Reduced motion: no entrance animation, no scroll reveal, poster instead of video.
- `npm run lint`, `npm test` and `npm run build` all pass.
